# نواة ERP الجامعي - المرحلة 1

أساس برمجي حقيقي لمقترح منظومة ERP الجامعية، يغطي **النواة (الهوية والصلاحيات والتدقيق) وخدمات شؤون الطلاب** (إفادة دوام، كشف علامات، عذر امتحاني) بمسار كامل: تقديم، فحص آلي، اعتماد الموظف، وثيقة موقعة برمز QR، وتحقق عام.

- **بلا اعتماديات خارجية:** Node.js 22.5+ فقط (HTTP وSQLite وTLS-ready وcrypto مدمجة). لا `npm install`، ما يسهّل تدقيق الكود أمنياً ويقلل مخاطر سلسلة التوريد.
- **قاعدة البيانات:** SQLite (ملف واحد) بترحيلات مرقمة في `server/migrations`. طبقة الوصول معزولة في `server/db.js` لتسهيل الانتقال إلى PostgreSQL عند الحاجة.

## التشغيل السريع

```bash
node -v                      # يجب أن يكون 22.5 أو أحدث
cp .env.example .env         # عدّل القيم
npm run seed -- --demo       # حسابات تجريبية (للتجربة المحلية فقط)
npm start                    # http://127.0.0.1:3000
npm test                     # اختبارات التكامل (28)
```

التهيئة تنشئ حسابات الإدارة فقط (`admin`, `staff1`, `auditor1`) ولا تنشئ أي طالب. مع `--demo` تكون كلمة المرور `Demo#2026pass` (للتجربة المحلية فقط)، وبدونه تُولَّد كلمات مرور عشوائية تُطبع مرة واحدة.

## تسجيل الطلاب

يدخل الموظف (`staff1`) أو المدير → **تسجيل الطلاب** → **تسجيل طالب جديد**، ويملأ النموذج بأقسامه: البيانات الشخصية، الاتصال والسكن، الشهادة الثانوية، القيد الأكاديمي، ولي الأمر والطوارئ. عند الحفظ يُولَّد الرقم الجامعي (`السنة-0001`) وكلمة مرور مؤقتة تُعرض مرة واحدة، ويُلزَم الطالب بتغييرها عند أول دخول. من **سجل الطلاب** يمكن البحث والتصفية وعرض الملف وتعديله وإعادة تعيين كلمة المرور. البرامج الأكاديمية تُدار من شاشة الإدارة (الأسماء المبدئية أمثلة تُعدَّل).

## هيكل المشروع

```
server/
  index.js, app.js        الإقلاع وتجميع المكونات
  config.js               الإعدادات (.env) ومفتاح التوقيع
  db.js                   SQLite والترحيلات والمعاملات
  security.js             scrypt، الرموز، HMAC، محدد المعدل
  audit.js                سجل تدقيق متسلسل بالبصمات
  permissions.js          مصفوفة الأدوار والصلاحيات (RBAC)
  http.js, routes.js      الخادم والمسارات والترويسات الأمنية
  qr.js                   مولّد QR محلي
  services/               auth, requests, rules, documents
  migrations/001_init.sql المخطط وبيانات الخدمات والقواعد
public/                   الواجهة (HTML/CSS/JS بلا سكربتات مضمّنة)
scripts/seed.js           تهيئة البيانات
test/api.test.js          اختبارات التكامل
docs/                     المعمارية وخارطة الطريق والأمن
```

## الأدوار

| الدور | يستطيع |
|---|---|
| طالب | تقديم طلباته ومتابعتها وعرض وثائقه |
| موظف | مراجعة كل الطلبات، الاعتماد والرفض، الإحصاءات |
| مدقق | قراءة الطلبات والتدقيق والتحقق من السلسلة (بلا اعتماد) |
| مدير النظام | كل ما سبق + المستخدمون والذمم وقواعد الفحص الآلي |


## بوابة الطالب (بنمط تطبيق الجوال)

بعد دخول الطالب (الرقم الجامعي + كلمة المرور المؤقتة ثم تغييرها) تظهر واجهة من خمس شاشات بشريط تنقل سفلي:

| الشاشة | المحتوى |
|---|---|
| الرئيسية | التحية، أبرز الأخبار، أزرار المعاملات السريعة |
| دليل المواد | مواد برنامجه حسب السنة والفصل |
| علاماتي | بطاقات ناجح/راسب بعلامة نظرية وعملية وكلية، المعدل، «عرض العلامات السابقة» لإعادة المقرر |
| الأخبار | التعاميم والأخبار مع التثبيت |
| المعاملات | معاملاتي وحالتها، وزر + لمعاملة جديدة بثلاث خطوات (النوع، البيانات، المراجعة والتأكيد) |

وفي القائمة الجانبية (الصورة الشخصية): بياناته، إضافة شكوى، تعديل معلومات الاتصال، تغيير كلمة المرور، التحقق من وثيقة، تسجيل الخروج.
الخدمات: إفادة دوام، كشف علامات، عذر امتحاني، طلب سنة امتياز، طلب حياة جامعية (وتُضاف خدمات جديدة بصف في جدول `service_types`).

## قسم الموظف: «شؤون الطلاب» (مدمج)

شاشة واحدة تجمع إحصاءات الطلبات، **طابور الطلبات** (اعتماد/رفض مع الفحص الآلي)، **سجل الطلاب**، و**تسجيل طالب جديد**، والانتقال من الطلب إلى ملف الطالب مباشرة. إلى جانبها: «المواد والعلامات» (إضافة مقررات وإدخال العلامات) و«الأخبار والشكاوى» (نشر الأخبار والرد على الشكاوى).

## ملف العرض المستقل

```bash
node --disable-warning=ExperimentalWarning scripts/build-demo.js   # يُنتج demo/university-portal-demo.html
```
ملف واحد يُفتح بنقرتين دون خادم، فيه الواجهتان وبيانات خيالية وخادم وهمي داخل المتصفح. زر في أعلاه يبدّل بين «طالب» و«موظف» والبيانات مشتركة (قدّم معاملة كطالب ثم اعتمدها كموظف).


## تطبيق الجوال (PWA)

الواجهة قابلة للتثبيت على الهاتف كتطبيق: أيقونة على الشاشة الرئيسية وفتح بملء الشاشة. الملفات: `public/manifest.webmanifest` و`public/sw.js` و`public/pwa.js` و`public/offline.html` و`public/icons/`.

- **أندرويد (Chrome):** افتح الرابط ← القائمة ⋮ ← «تثبيت التطبيق» (أو «إضافة إلى الشاشة الرئيسية»).
- **آيفون (Safari):** افتح الرابط ← زر المشاركة ← «إضافة إلى الشاشة الرئيسية».
- **شرط الإنتاج:** التثبيت الكامل وعامل الخدمة يتطلبان **HTTPS**. على `http://` عبر الشبكة المحلية يعمل الموقع كاملاً ويمكن إضافة اختصار، لكن دون عامل الخدمة.
- **الخصوصية:** عامل الخدمة لا يخزّن أي استجابة من `/api/`؛ تُخزَّن الملفات الثابتة فقط. عند تعديل ملفات الواجهة غيّر `VERSION` في `sw.js` لإجبار الأجهزة على التحديث.

### التجربة على الهاتف عبر الشبكة المحلية (للاختبار فقط)
1. في ملف `.env` ضع `HOST=0.0.0.0` ثم شغّل `npm start`.
2. اعرف عنوان IP لجهازك (`ipconfig` في ويندوز، ابحث عن IPv4 مثل 192.168.1.20).
3. من هاتف على نفس شبكة Wi-Fi افتح `http://عنوان-IP:3000`.
4. أعد `HOST=127.0.0.1` بعد الانتهاء، ولا تترك النظام مفتوحاً على الشبكة بحسابات `--demo`.
