# المعمارية

## الصورة العامة

```
المتصفح (public/) ──HTTPS──► server/http.js ──► routes.js ──► services/*
                                   │                             │
                          ترويسات أمنية، حدود الحجم،       قواعد العمل (rules، requests، documents)
                          جلسات، RBAC                           │
                                                          SQLite (db.js) + data/uploads
                                                          audit_log (سلسلة بصمات)
```

## قرارات تصميمية

- **سلسلة التدقيق:** كل سجل يضم بصمة السابق؛ المشغِّلات تمنع UPDATE/DELETE، و`/api/audit/verify` يكشف أي كسر. من يملك الملف نفسه يستطيع تعطيل المشغِّلات، لذلك تُصدَّر بصمة آخر سجل دورياً إلى جهة خارجية (انظر خارطة الطريق).
- **الوثائق:** تُخزَّن لقطة JSON قانونية (مفاتيح مرتبة) وقت الإصدار. تغيّر بيانات الطالب لاحقاً لا يغيّر ما صدر. التحقق يعيد حساب البصمة والتوقيع من الصف المخزَّن.
- **التوقيع:** HMAC بمفتاح الخادم يثبت الأصالة داخل الجامعة. لتحقق جهات خارجية دون الوثوق بالخادم يلزم توقيع غير متماثل (انظر خارطة الطريق).
- **الجلسات:** رمز عشوائي 256 بت في كوكي `HttpOnly; SameSite=Strict`، ويُخزَّن في القاعدة مجزَّأً (SHA-256) فلا يفيد تسريب القاعدة في انتحال الجلسات.
- **CSRF:** `SameSite=Strict` + قبول `application/json` فقط في الطلبات المغيِّرة.
- **المرفقات:** تُفحص بالمحتوى الفعلي (PDF/PNG/JPG)، تُخزَّن بأسماء عشوائية بصلاحيات 0600، وتُقدَّم `attachment` مع `nosniff`، وتُتحقَّق بصمتها عند التنزيل.
- **أخطاء القراءة:** الطالب الذي يطلب سجلاً لغيره يتلقى 404 لا 403 كي لا يُكشف وجوده.

## نقاط التوسعة

- وحدة جديدة = ملف في `services/` + مسارات في `routes.js` + ترحيل `00N_*.sql` + صلاحيات في `permissions.js`.
- خدمة جديدة لشؤون الطلاب = صف في `service_types` (الحقول معرَّفة بـ JSON) دون تعديل الكود، وقاعدة في `rules` إن لزم.
